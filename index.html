Lesson 1

What is an algorithm?

An algorithm is a set of clear steps, written in the right order, that solves a problem or completes a task.

You already use algorithms every day. You just do not call them that.

Example 1: brushing your teeth

  1. Pick up the toothbrush.
  2. Put toothpaste on the brush.
  3. Brush your teeth for two minutes.
  4. Rinse your mouth with water.
  5. Rinse the brush and put it away.

This is an algorithm. It has a start, a list of steps in order, and it ends with the job done.

Example 2: the order matters

Look at the same steps in the wrong order: put the brush away, rinse your mouth, brush your teeth, put toothpaste on, pick up the brush. Nothing works. The order of the steps is part of the algorithm.

Example 3: a computer algorithm

Problem: add two numbers.

  1. Get the first number.
  2. Get the second number.
  3. Add them together.
  4. Show the answer.

What makes a good algorithm? Six properties

PropertyWhat it meansExample
InputIt may take in data to work with.The two numbers to add
OutputIt must produce at least one result.The sum
Clear (definite)Each step has only one possible meaning."Add the numbers" is clear. "Do something with the numbers" is not.
FiniteIt must finish after a limited number of steps. It cannot go on forever.Five steps, then stop
OrderedThe steps are in the correct sequence.Get the numbers before adding them
EffectiveEvery step is simple enough to actually be done."Add" is doable. "Find the biggest number in the universe" is not.

Clear versus unclear

Unclear1. Get some bread.
2. Put stuff on it.
3. Eat.

What stuff? How much? Which bread?
Clear1. Take two slices of bread.
2. Spread butter on one slice.
3. Place one slice of cheese on top.
4. Cover with the second slice.
5. Eat.
RememberA computer does exactly what you tell it, nothing more and nothing less. It cannot guess what you meant. That is why every step must be clear.

Three ways to write an algorithm

The same algorithm can be written in three ways. They all say the same thing. They just look different.

  1. Plain English steps: normal sentences, numbered.
  2. Pseudocode: short, structured, code-like lines. It is not a real programming language, so nothing can "break". It is a bridge between English and real code.
  3. Flowchart: a picture made of shapes and arrows.

The same problem in all three ways

Problem: Ask for two numbers and show their sum.

1. Plain English
  1. Start.
  2. Ask the user for the first number and the second number.
  3. Add the two numbers and call the result sum.
  4. Show sum.
  5. Stop.
2. Pseudocode 
START
INPUT num1, num2
sum = num1 + num2
OUTPUT sum
END

What is a variable?

A variable is a labelled box in the computer's memory that holds one value. The label is the variable's name. The value inside can change.

Picture itThe line age = 12 means: "Take a box, label it age, and put 12 inside." Later, age = 13 means: throw away the 12 and put 13 inside. The box is the same. The content changed.

The line that confuses most beginners: count = count + 1

In maths, "count = count + 1" is impossible. In an algorithm, the = means "store". So read it from the right side first:

  1. Look at the current value in the box count. Say it is 4.
  2. Add 1 to it. That makes 5.
  3. Put 5 back into the box count. The old 4 is gone.

Lesson 3

The three building blocks of every algorithm

Every algorithm ever written, from a simple calculator to a banking system, is built from only three ideas. Learn these and you can read any algorithm.

1. Sequence: do things one after another

Steps run in order, top to bottom, with no skipping.

INPUT length, width
area = length * width
OUTPUT area

Real life: put on socks, then put on shoes.

2. Selection: make a choice

The algorithm asks a yes/no question and follows a different path depending on the answer. Also called a decision or branching.

INPUT age
IF age >= 18 THEN
    OUTPUT "You can vote"
ELSE
    OUTPUT "You cannot vote yet"
END IF

Real life: if it is raining, take an umbrella. Otherwise, wear sunglasses.

3. Iteration: repeat

The algorithm repeats some steps again and again until a condition says stop. Also called a loop.

i = 1
WHILE i <= 3 DO
    OUTPUT "Hello"
    i = i + 1
END WHILE

This prints Hello three times. Real life: keep stirring the soup until it boils.

Important: every loop needs three things
  1. A starting value (i = 1)
  2. A condition that decides whether to keep going (i <= 3)
  3. A change inside the loop that moves toward stopping (i = i + 1)
If you forget the change, the condition never becomes false and the loop runs forever. That is called an infinite loop, and it breaks the "finite" rule from lesson 1.

Lesson 4

Pseudocode, part 1: the basics

What is pseudocode?

Pseudocode (say it: SOO-doh-code) is a way of writing an algorithm using short, structured lines that look a little like a programming language but are really just careful English. The word "pseudo" means "pretend" or "not real". No computer runs pseudocode. People read it.

Think of it like thisAn architect draws a plan before the builders start. Pseudocode is the plan. Real code (Python, Java, JavaScript) is the building. If the plan is wrong, the building will be wrong, so we get the plan right first.

Why do we use it?

  • It lets you think about the logic only. You do not need to worry about brackets, colons or spelling rules of a real language.
  • Anyone can read it. A person who knows Python and a person who knows Java can both understand the same pseudocode.
  • It is easy to change. Fixing a plan is quicker than fixing a finished program.
  • It translates into any language. Once you have good pseudocode, writing real code is mostly a matter of changing the words.

The rules we follow in this course

Pseudocode has no official rulebook, but good pseudocode follows habits that make it easy to read. These are the habits used on this website.

  1. One instruction per line. Do not squeeze two actions into one line.
  2. Keywords are in CAPITAL LETTERS such as INPUT, OUTPUT, IF, WHILE. This makes the structure stand out from your variable names.
  3. Indent the lines inside a block. Everything inside an IF or a loop is pushed in by 4 spaces. The indent shows what belongs to what.
  4. Close every block. Every IF ends with END IF. Every WHILE ends with END WHILE. Every FOR ends with END FOR.
  5. Use meaningful names. totalMarks tells you what it is. x does not.
  6. Put text in quotation marks. OUTPUT "Hello".
  7. Explain tricky lines with a comment that starts with //. The computer (and the reader) ignores comments as instructions. They are notes to the human.

Variables: labelled boxes

A variable is a named place in the computer's memory that stores one value. You choose the name. You can look at the value, and you can replace it.

Giving a variable a value is called assignment. We write it with = and read it as "gets" or "becomes":

age = 12          // the box called age now holds 12
name = "Ada"      // the box called name now holds the text Ada
age = age + 1     // read the old value, add 1, store 13 back
Rule for assignmentThe variable that receives the value is always on the left of the =. The calculation is on the right. The right side is worked out first, then the answer is stored on the left.

Some textbooks write assignment with an arrow, age ← 12, to show that the value flows into the box. It means exactly the same as age = 12. If your teacher or exam uses the arrow, use the arrow.

INPUT and OUTPUT

INPUT receives a value from the user and stores it in a variable. OUTPUT (some books say PRINT or DISPLAY) shows a value.

INPUT name
OUTPUT "Hello, " + name
OUTPUT "Welcome to the course"

If the user types Ada, the screen shows:

Hello, Ada
Welcome to the course

The + between text pieces joins them. Joining text is called concatenation. Notice the space inside "Hello, ". Without it you would see "Hello,Ada".

What is MOD useful for?

  • Even or odd: n MOD 2 = 0 means even.
  • Multiples: n MOD 5 = 0 means n is a multiple of 5.
  • Last digit: 1234 MOD 10 = 4.
  • Going round in circles: hours on a clock, days of the week.

The order of calculation

When a line has several operators, they are not done simply left to right. The order is:

  1. Brackets first.
  2. Then power (^).
  3. Then *, /, DIV, MOD (left to right).
  4. Then + and - (left to right).

A. Selection: IF

1. IF ... THEN (one path)

Do something only when a condition is TRUE. If it is FALSE, skip it and carry on.

INPUT price
IF price > 5000 THEN
    price = price - 500      // 500 discount on big purchases
END IF
OUTPUT price

2. IF ... THEN ... ELSE (two paths)

One thing happens if the condition is TRUE. A different thing happens if it is FALSE. Exactly one of the two always runs.

INPUT age
IF age >= 18 THEN
    OUTPUT "Adult"
ELSE
    OUTPUT "Child"
END IF

3. ELSE IF (three or more paths)

When there are more than two outcomes, chain the questions. The computer asks them from the top and stops at the first TRUE one.

    OUTPUT "A"

    OUTPUT "B"

B. Iteration: loops

A loop repeats a group of lines. Writing the same line five times is silly. Writing it once inside a loop that runs five times is clever. There are three kinds of loop in pseudocode.

1. WHILE ... DO ... END WHILE (check first, then repeat)

The condition is checked before each round. If it is TRUE, run the body. If it is FALSE, skip the whole loop. Use WHILE when you do not know in advance how many rounds are needed.

i = 1
WHILE i <= 3 DO
    OUTPUT "Hello"
    i = i + 1
END WHILE
OUTPUT "Done"

A WHILE loop can run zero timesIf the condition is FALSE the very first time, the body never runs at all. Try it with i = 10: 10 <= 3 is FALSE at once, so "Hello" is never shown.

2. FOR ... TO ... END FOR (a counted loop)

Use FOR when you know how many times to repeat. The loop sets up the counter, checks it and adds to it for you. The three jobs (start value, condition, change) are all packed into one line.

FOR i = 1 TO 5
    OUTPUT i
END FOR

This outputs 1, 2, 3, 4, 5. The counter i starts at 1, runs the body, goes up by 1 automatically, and stops after 5.

Lesson 6

Pseudocode, part 3: procedures, translating from English, and good style

Procedures and functions: reusable named blocks

Sometimes you need the same group of lines in many places. Instead of copying them each time, give the group a name and use that name whenever you need it. There are two kinds:

  • A procedure does a job (for example, shows a greeting). It does not hand back an answer.
  • A function works something out and hands back an answer using RETURN.
PROCEDURE greet(name)
    OUTPUT "Hello, " + name
END PROCEDURE

FUNCTION circleArea(r)
    area = 3.14 * r * r
    RETURN area
END FUNCTION

START
INPUT radius
result = circleArea(radius)      // use the function, store its answer
OUTPUT result
CALL greet("Ada")                // run the procedure
END
WordMeaning
ParameterA placeholder name inside the brackets of the definition. In circleArea(r), r is a parameter. It stands for "whatever radius I am given".
ArgumentThe real value you pass in when you use it. In circleArea(radius), the value stored in radius is the argument.
RETURNSends the answer back to the line that used the function, and ends the function.
CALLMeans "run this procedure now".

Trace with radius = 2: the function receives r = 2. It works out area = 3.14 × 2 × 2 = 12.56. It returns 12.56. That is stored in result, and the output is 12.56.

Turning English into pseudocode: a 5-step method

  1. Read the problem and underline the verbs and conditions.
  2. Find the inputs (things you must ask for) and the outputs (things you must show).
  3. Spot the structure words using the table below.
  4. Write the lines in order, one action per line, with correct indentation.
  5. Test it with at least two different inputs.
If the English says...Use...

From pseudocode to real code

Pseudocode is a stepping stone. Here is the same even-or-odd algorithm in pseudocode and in Python, a real language:

Pseudocode 
INPUT number
IF number MOD 2 = 0 THEN
    OUTPUT "Even"
ELSE
    OUTPUT "Odd"
END IF
Python 
number = int(input("Number: "))
if number % 2 == 0:
    print("Even")
else:
    print("Odd")

Find the bug (every answer is already filled in)

Bug 1: a missing END IF

    OUTPUT "Adult"
ELSE

Problem: the IF is never closed, so "Done" looks like it belongs to the ELSE.

Bug 2: text without quotation marks

Problem: without quotes, Hello looks like a variable name, and no variable has been made.

Bug 3: a loop that never ends

    OUTPUT i
END WHILE
Problems: (1) i has no starting value, (2) nothing changes i, so the condition never becomes FALSE.

i = 1

    OUTPUT i

Lesson 7

Flowchart symbols: all 14 of them

A flowchart is a diagram that shows an algorithm using shapes joined by arrows. Each shape has one job, and each job has its own shape. If you use the right shape, anyone in the world can read your flowchart without asking you a single question.

There are 14 symbols in this lesson. The first five are the core ones that you will use in almost every flowchart. The other nine are extra symbols that you will meet in textbooks, exams and real projects. Learn all of them, one at a time.

Part A: the 5 core symbols

How to remember the core four shapes Rounded = the edges of the story (start and end). Rectangle = work being done. Slanted (parallelogram) = data moving in or out, like a ramp. Diamond = a crossroads where you must choose a road.

Lesson 8

Rules for drawing a good flowchart

  1. One Start, at the top. Every flowchart has exactly one Start symbol.
  2. Flow goes top to bottom (and left to right where needed). Do not make the reader hunt for the next step.
  3. Every shape is joined by an arrow. The arrowhead shows the direction. No loose boxes.
  4. A rectangle or parallelogram has one arrow in and one arrow out.
  5. A diamond has one arrow in and exactly two arrows out, labelled Yes and No. The question must be answerable with yes or no.
  6. Keep the text short. Write sum = a + b, not a whole paragraph.
  7. Paths must join up again or reach an End. Do not leave a path hanging.
  8. Loops go back with an arrow that returns to the decision diamond (or to an earlier step).
  9. Always finish with End.
  10. Use a hexagon for a FOR loop and label its two exits Body and Done.
  11. Connectors come in matching pairs (same letter or number). Use them only when the chart is too big to draw without long, crossing arrows.
  12. Use each symbol for its own job everywhere. Never use a rectangle for input or a diamond for a calculation.

Common mistakes and how to fix them

Lesson 10

More flowcharts: using the extra symbols

In lesson 9 you drew flowcharts with the five core symbols. Now we use the remaining symbols in real examples. Each example shows the pseudocode first, then the flowchart, then how to read it.

1. The hexagon: a FOR loop

The hexagon (preparation symbol) holds the whole FOR line. It sets i to its start value, checks it, and adds 1 after each round. Because it does all three jobs, you do not need a separate "i = i + 1" box.

START
FOR i = 1 TO 5
    OUTPUT i
END FOR
END
  1. The flow enters the hexagon. i becomes 1.
  2. The hexagon checks: is i still within 1 to 5? If yes, leave by the Body arrow.
  3. The body runs: Output i.
  4. The loop-back arrow returns to the hexagon. i goes up by 1 automatically.
  5. After i = 5 has been done, the next check finds i = 6 is out of range, and the flow leaves by the Done arrow to End.

It outputs 1, 2, 3, 4, 5. The hexagon exit labelled Done means "all rounds finished".

2. FOR loop with a total: average of five numbers

START
total = 0
FOR i = 1 TO 5
    INPUT number
    total = total + number
END FOR
average = total / 5
OUTPUT average
END

Compare this to the trace table in lesson 5. With numbers 4, 8, 6, 2, 10, the total builds up 4, 12, 18, 20, 30. After the loop the flow takes the Done exit and calculates average = 30 / 5 = 6.

Where does total = 0 go?Before the hexagon. If you put it inside the loop, total would be reset to 0 on every round and you would lose the running total.

3. REPEAT ... UNTIL: the decision comes after the body

START

OUTPUT "Correct!"
END

How to spot a REPEAT UNTIL in a flowchart: the Input (the body) comes before the diamond, and the loop-back arrow leaves the No exit and returns to the body. Compare with the WHILE loop in lesson 9 (sum from 1 to N), where the diamond comes first. That position tells you which loop it is.

8. Different kinds of input and output, and annotations

Lesson 12

Design your own algorithm: a 6-step method

When you are given a problem, do not start by drawing. Follow these steps.

  1. Read the problem twice. Say it in your own words.
  2. Find the output. What answer must the algorithm produce?
  3. Find the input. What information does it need to start?
  4. Find the process. What calculations, choices or repeats turn the input into the output? Is it sequence, selection, iteration, or a mix?
  5. Write it in plain steps, then pseudocode, then draw the flowchart.
  6. Test it with simple numbers, including boundary cases, using a trace table.

Three possible answers means two questions. First ask "is it greater than 0?". If not, ask "is it less than 0?". If not that either, it must be zero.
