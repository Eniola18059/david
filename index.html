Why loops?

Imagine printing the numbers 1 to 100. You could write Console.WriteLine one hundred times, but that is slow to write, hard to change, and easy to get wrong. A loop lets you write the instruction once and tell C# how many times, or for how long, to repeat it.

Every loop has the same three ingredients, whatever its syntax:

  • A starting point: where counting or checking begins.
  • A condition: a true/false question asked before (or after) each turn. While the answer is true, the loop continues.
  • A change: something that moves the loop toward finishing, usually adding 1 to a counter. Without it, the loop never ends.
Start→Check condition→ true →Run body→Update→ back to check

When the check says false, C# skips the body and carries on with the code after the loop. One run through the body is called an iteration.

C# gives you four loops: for, while, do-while and foreach. They can often do the same job, so the real skill is choosing the one that reads most clearly.

The for loop

Use for when you know how many times to repeat, or you need a counter. It puts all three ingredients on one line, separated by semicolons.

for (int i = 1; i <= 5; i++)
{
    Console.WriteLine("Round " + i);
}
Round 1 Round 2 Round 3 Round 4 Round 5

Reading the three parts

PartExampleWhen it runs
Initializerint i = 1Once, before the first check. Declares the counter. The name i is a convention for “index”, and the counter exists only inside the loop.
Conditioni <= 5Before every iteration. If false, the loop stops.
Iteratori++After every iteration. i++ means “add 1 to i”.

The order matters: initialize, check, run body, iterate, check again, and so on. You can see this order in the live loop at the top of the page.

Counting in other ways

The iterator can be anything. Count by twos, or count down:

for (int i = 0; i <= 10; i += 2) Console.Write(i + " ");   // 0 2 4 6 8 10
for (int i = 5; i > 0; i--)       Console.Write(i + " ");   // 5 4 3 2 1

Looping through an array by index

Arrays start counting at 0, and Length tells you how many items there are. So the last valid index is Length - 1, which is why the condition is < and not <=.

string[] fruits = { "mango", "pawpaw", "orange" };
for (int i = 0; i < fruits.Length; i++)
{
    Console.WriteLine($"{i}: {fruits[i]}");
}
0: mango 1: pawpaw 2: orange
Worked example: sum 1 to 100. Create a variable to hold the running total outside the loop, then add to it on each turn. 
int total = 0;
for (int n = 1; n <= 100; n++)
{
    total += n;      // same as total = total + n
}
Console.WriteLine(total);   // 5050

The while loop

Use while when you don’t know in advance how many turns you need. You only know the condition that keeps the loop going. It checks first, so if the condition is false at the start, the body never runs at all.

int money = 1000;
int days = 0;
while (money > 0)
{
    money -= 300;     // spend 300 each day
    days++;
}
Console.WriteLine($"Money lasted {days} days");
Money lasted 4 days

Here you did not decide “4” anywhere. The loop worked it out. Notice that you are responsible for the change step: money -= 300 is what eventually makes the condition false.

Typical use: keep asking until the input is valid

string input = "";
while (input != "yes")
{
    Console.Write("Type yes to continue: ");
    input = Console.ReadLine();
}

The do-while loop

This is while with the check moved to the end. The body always runs at least once, then the condition decides whether to go again. Note the semicolon after the closing parenthesis.

int pin;
do
{
    Console.Write("Enter a 4-digit PIN: ");
    pin = int.Parse(Console.ReadLine());
}
while (pin < 1000 || pin > 9999);

A menu or a PIN prompt fits perfectly: you must ask at least once before you can judge the answer. A plain while would force you to invent a fake starting value first.

The foreach loop

When you just want every item in a collection and don’t care about positions, use foreach. There is no counter, no condition, no iterator to get wrong. C# hands you each item in turn.

string[] students = { "Ada", "Tunde", "Ngozi" };
foreach (string name in students)
{
    Console.WriteLine("Hello, " + name);
}
Hello, Ada Hello, Tunde Hello, Ngozi

Read it aloud: “for each name in students”. It works on arrays, List<T>, strings (character by character) and anything else enumerable.

var scores = new List<int> { 70, 85, 92 };
int sum = 0;
foreach (int s in scores) sum += s;
Console.WriteLine(sum / (double)scores.Count);   // 82.33...
Read-only variable. You cannot assign to the loop variable (name = "x" is a compile error), and you must not add or remove items from the collection while looping over it, or C# throws an exception. If you need to change items or know their position, use for.

Steering a loop: break and continue

break leaves the loop immediately. continue abandons the current iteration and jumps to the next one.

for (int i = 1; i <= 10; i++)
{
    if (i == 3) continue;   // skip 3
    if (i == 6) break;      // stop completely at 6
    Console.Write(i + " ");
}
1 2 4 5

A common real use of break is searching: stop as soon as you find what you want, rather than checking the rest.

int[] ids = { 14, 27, 31, 42 };
int foundAt = -1;
for (int i = 0; i < ids.Length; i++)
{
    if (ids[i] == 31) { foundAt = i; break; }
}
Console.WriteLine(foundAt);   // 2

Inside a loop that must run until you say stop, while (true) plus a break is a legitimate pattern, provided there is a reachable break.

Nested loops

A loop inside a loop. The inner loop completes all of its turns for every single turn of the outer loop. Think of a clock: the minute hand goes round fully for each step of the hour hand.

for (int row = 1; row <= 3; row++)
{
    for (int col = 1; col <= 4; col++)
    {
        Console.Write("* ");
    }
    Console.WriteLine();   // new line after each row
}
* * * * * * * * * * * *

The body runs 3 × 4 = 12 times. Use different counter names (row, col, or i, j) so they don’t clash. When the inner loop’s limit depends on the outer counter, you get shapes:

for (int i = 1; i <= 4; i++)
{
    for (int j = 1; j <= i; j++) Console.Write("#");
    Console.WriteLine();
}
# ## ### ####

Multiplication tables are the classic use: Console.Write($"{a * b,4}") inside two nested loops from 1 to 12 prints a neat grid. Be careful with big numbers: two nested loops of 10,000 each run 100 million times.

break only exits the innermost loop it sits in. To escape both, set a flag variable or move the loops into a method and use return.

Common mistakes

1. The infinite loop

The condition never becomes false, usually because the change step is missing or goes the wrong way.

int x = 1;
while (x <= 5)
{
    Console.WriteLine(x);
    // forgot x++  → prints 1 forever
}

If your program hangs or floods the console, stop it with Ctrl + C, then check: does something inside the loop move it toward the exit?

2. Off-by-one errors

Using <= where you meant <, or starting at 1 instead of 0. Looping an array with i <= fruits.Length reaches an index that doesn’t exist and throws IndexOutOfRangeException. Test the first and last turn by hand.

3. A stray semicolon

for (int i = 0; i < 3; i++);      // this ; is the entire body!
{
    Console.WriteLine("hi");      // runs once, after the loop
}

4. Using the counter outside the loop

A variable declared in for (int i ...) disappears when the loop ends. If you need its final value, declare it before the loop.

5. Changing a collection inside foreach

Adding or removing items mid-loop throws InvalidOperationException. Collect the changes and apply them after, or loop backwards with for.

Which loop should I use?

SituationBest loop
I know how many times, or I need the indexfor
I want every item in a collectionforeach
Repeat until something changes; might need zero runswhile
Must run at least once, then repeat on a conditiondo-while

When two loops would work, pick the one a stranger could understand fastest. foreach is usually the clearest for collections, and it removes a whole class of off-by-one bugs.

Practice

Try each one in a console project (dotnet new console) before opening the answer. Typing the code yourself is where the learning happens.

1. Print the even numbers from 2 to 20 
for (int i = 2; i <= 20; i += 2)
    Console.WriteLine(i);
2. Count down from 10 to 1, then print “Go!” 
for (int i = 10; i >= 1; i--)
    Console.WriteLine(i);
Console.WriteLine("Go!");
3. Find the largest number in an array 
int[] nums = { 12, 99, 4, 57 };
int max = nums[0];
foreach (int n in nums)
    if (n > max) max = n;
Console.WriteLine(max);   // 99

Start max from the first item, not from 0, so the code also works when every number is negative.

4. FizzBuzz: 1 to 30, “Fizz” for multiples of 3, “Buzz” for 5, “FizzBuzz” for both 
for (int i = 1; i <= 30; i++)
{
    if (i % 15 == 0) Console.WriteLine("FizzBuzz");
    else if (i % 3 == 0) Console.WriteLine("Fizz");
    else if (i % 5 == 0) Console.WriteLine("Buzz");
    else Console.WriteLine(i);
}

Check the “both” case first, otherwise multiples of 15 would match the Fizz test and stop there.

5. Guessing game: keep asking until the player guesses 7 
int guess;
do
{
    Console.Write("Guess the number: ");
    guess = int.Parse(Console.ReadLine());
}
while (guess != 7);
Console.WriteLine("Correct!");
6. Print a triangle of stars with 5 rows 
for (int i = 1; i <= 5; i++)
    Console.WriteLine(new string('*', i));

Bonus: rewrite it with a nested loop instead of new string.
